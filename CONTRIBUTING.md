# Contributing

Thanks for helping. Bug reports, new site rules and fixes are all welcome.

## Reporting a problem

Open an issue and include:

- the site address,
- your browser and its version,
- what you expected and what happened (a screenshot helps).

## Changing the code

1. Fork the repository and create a branch.
2. Make your change. Keep it focused on one thing.
3. Run `npm install` once, then `npm run test:unit`. If you touched the extension itself, also run `npm run test:e2e` and, if you have Firefox, `npm run test:firefox`.
4. Open a pull request and describe what it changes and how you tested it.

The maintainer reviews every pull request before it is merged. The unit tests run automatically on each pull request.

## Rules for changes

- The extension must never click "accept" or send data anywhere. Pull requests that add logging, network requests or tracking will not be merged.
- Don't edit files in `extension/vendor/autoconsent/` by hand. They are generated by `tools/vendor.mjs` (see "Updating the rules" in the README).
- New permissions in `extension/manifest.json` need a clear reason in the pull request.
